# Reproducing the Paper's Results

This document maps the manuscript's main results to the exact scripts that
produce them, records the compute environment used, and states which data can
be redistributed and which cannot (with the reasons and the workarounds).

---

## 1. Software environment used for the paper

| Item | Value |
|---|---|
| OS | Windows 10 x64 |
| Python | 3.12.7 (64-bit) |
| Key packages | langgraph 1.2.9, numpy 1.26.4, pandas 2.2.2, scipy 1.13.1, scikit-learn 1.5.1, matplotlib 3.9.2, openpyxl 3.1.5, xlrd 2.0.2, Pillow 12.3.0, PyMuPDF 1.26.3, requests 2.32.3 (see [`requirements.txt`](../requirements.txt)) |
| Local inference | Ollama / llama.cpp `llama-server`, GGUF-quantized models, context window 32768 |
| Cloud inference | OpenAI-compatible endpoints (DeepSeek, Zhipu BigModel) |
| Hardware (local arms) | Single consumer GPU; ≥ 16 GB VRAM for 8B–14B, ≥ 24 GB VRAM for 24B–30B models |
| Hardware (cloud arm) | Any modern workstation; no GPU required |

Determinism notes:

- Inference uses `temperature=0.1`; structured outputs (planning JSON) are
  stable but not bit-identical across backend versions — expect small
  numerical variation in LLM-driven scores when re-running with a different
  model build.
- Everything outside the LLM is deterministic: parsers, tool computations,
  scoring scripts, and the rule-based planner (`--no-llm`) reproduce exactly.
- Benchmark construction uses fixed random seeds (`--seed`, default 42) and
  atomic 0.5°/1° spatial block splits to prevent train/test leakage.

2. Standalone GeoChemReasoner startup
GeoChemReasoner can be started independently using the main agent entry script. From the repository root, install the required dependencies and run:
pip install -r requirements.txt
python "core_code/script/start_agent.py"
The start_agent.py script provides the standalone entry point for running the complete GeoChemReasoner agent. It initializes the agent architecture, loads the registered professional tools, connects to the configured language-model backend, and executes a user-defined geochemical analysis.
Before starting the agent, the language-model backend must be configured through the following environment variables or an accompanying .env file:
LLM_API_BASE
LLM_API_KEY
LLM_MODEL_NAME
The model endpoint and model identifier are supplied entirely through the runtime environment and are not hard-coded in the startup script.
3. Main results → scripts
The main results reported for Tasks F and G were generated using three parallel execution configurations: the complete GeoChemReasoner agent, a standard ReAct agent, and a single-shot LLM baseline. All three evaluation entry scripts are located in:
core_code/script/
Configuration	Entry script	Description
Complete GeoChemReasoner	Task with GeoChemReasoner.py	Runs Tasks F and G using the complete GeoChemReasoner agent, including structured reasoning, registry-constrained tool execution, and evidence-synchronized observation.
Standard ReAct agent	Task with ReAct.py	Runs Tasks F and G using an agent based on the standard ReAct architecture, providing an agent-level comparison with the complete GeoChemReasoner architecture.
Single-shot LLM	Task with single llm.py	Runs Tasks F and G using direct single-shot LLM responses without the complete agent architecture or iterative ReAct control.


From the repository root, the three configurations can be started with the following commands:
python "core_code/script/Task with GeoChemReasoner.py"
python "core_code/script/Task with ReAct.py"
python "core_code/script/Task with single llm.py"
Each script is an independent entry point for running Tasks F and G under its corresponding execution configuration. The scripts use the same environment-based model configuration described in Section 1, allowing the three configurations to be evaluated under aligned model and runtime settings.
The complete GeoChemReasoner configuration evaluates the full SRE-ReAct architecture. The standard ReAct configuration provides an agent-based comparison for examining the contribution of structured execution control and evidence synchronization. The single-shot LLM configuration provides the non-agent baseline used to assess the contribution of agent-based planning and deterministic tool execution.
The outputs generated by these scripts provide the results reported in the manuscript, including task-completion rates, evaluation-criterion pass rates, and content-accuracy scores.
